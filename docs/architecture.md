# Architecture

The product has a loader-neutral core, two Minecraft-version adapters and thin native loader entries. Core policy/profile/geometry values must not import Minecraft or optional-mod classes. The native adapters own resource-manager, model-part, reload and renderer lifecycles. Shared runtime services receive each target’s admitted capabilities explicitly; consolidation must not replace them with compiler defaults. Modern ordinary-chest adaptation depends on the target’s native copper-isolation admission.

Lootr owns its container registrations, per-player opened state, loot, sounds and materials. Minecraft owns vanilla container semantics. This addon contributes selected presentation, without replacing gameplay or imposing a server component.

Effective vanilla models and their UVs are read-only inputs. Native adapters preserve source geometry and texture coordinates; unusual layouts need qualified mapping or an explicit profile. The addon publishes Lootr-specific outputs rather than vanilla resource overrides, and ships no replacement chest geometry. [Profiles](profiles.md) owns independent Models, Artwork, and Fresh Objects selections, per-slot precedence, and fallbacks. [Barrel rendering](barrels.md) owns Default's geometry and effective-artwork UV binding.

One compiler prepares a complete immutable resource generation from config/resource-pack profiles and admitted lower resources. Native publication checks the current generation and publishes model/texture/animation output together. Generated output cannot become its own input. A failed or stale candidate does not publish partially; retaining previous objects is valid only while their native lifecycle remains live.

Optional foreign classes must not resolve when their adapter is absent or disabled. Client rendering must not load on a dedicated server. Native and foreign subclass renderers need explicit scope admission; inheritance alone is not authority to modify their output.

The settings workspace declares a stable identity and Home page through re:form. Home links to settings and profile tools without opening an appearance editor. Category destinations have their own presentation identities; they do not create settings owners or change serialized fields. Opening Appearance retains the existing document and save path.

Settings persistence, retained editing, conflicts, references, commands and operation screens use public re:form services. One staged file owner reads and writes the existing format 1 `settings.json`; profile discovery, compilation and export remain domain operations. Profile initialization never writes settings. Ordinary control rendering and search use immutable cached metadata, without filesystem or resource analysis.

Resource reload captures that same settings store on a bounded worker. Native publication binds the consumed file revision to the new generated-pack identity. Save and reload resources retains the actual persistence receipt, then separately waits for native reload and verifies the active generation and current source. A failed or cancelled reload cannot erase a confirmed save. A native future completing without the matching new generation is insufficient to report application. Closing an editor or client retires its operation authority; it does not imply rollback of a completed write or native reload.

The build-only formal layer checks stated policy/publication models. It does not execute in Minecraft or establish Java translation correctness. [Verification](verification.md) owns the actual comparison and native evidence.

The core resource envelope captures a complete owned byte set in deterministic identity order. It defensively copies mutable input and offers independent read streams; it retains no live models, sprites or source handles. [Profiles](profiles.md#resource-limits) owns intake and publication limits; these are product policy rather than native format maxima. The native reload argument adapter appends one owned generation after a borrowed lower-stack view. Generation identity and close checks prevent stale suppliers from serving output; closing the layer never closes borrowed packs. Namespace discovery prepares the immutable generation once before native listeners consume it. The hook checks client-resource type so integrated-server data reloads keep their existing inputs.

[Barrel rendering](barrels.md) owns the shared shell, state/UV, lighting, culling and cache contract. Native section rebuilds remain Minecraft/Sodium’s responsibility.

## Isolated preview preparation

Draft preparation starts with re:form’s actual READ capture and binds its native-input/reference stamps to the current resource generation. It uses guarded lower sources, excluding the installed generated layer, and the same complete-settings compiler as reload. Frozen chest/barrel inputs own their selected bytes; they do not retain borrowed packs or source streams. Local profile enumeration is reusable within one read scope, with directory identity/listing and file-content checks; cached names cannot survive closure. No preview preparation seeds profiles, saves settings, installs resources, or initiates a reload.

Native barrel baking retains explicit material, tint, shading, and emission facts. Modern faces use the native material-selection path with captured animation metadata; material bindings can differ while sharing one texture. Native world-layer facts and the selected still frame’s alpha policy remain distinct, including the native single-frame shortcut. Its temporary native images reserve the shared workflow ledger before decoding; accounting is released only after their actual close. Outstanding viewport allocations can therefore refuse a later bake. Native chest preparation uses detached game parts and preserves emitted UVs, normals, and winding. Optional chest rig preparation resolves bounded frozen JPM dependencies before calling the installed data/cuboid factories. It does not call EMF’s model root, registration, render, or animation paths. Pose facts identify static lid progress, actual visible geometry under the native lid/lock attachments, and the absence of rig-animation evaluation or world inputs. A rig can place its visible lid under another attachment; an empty native lid control must not be presented as an animated open pose. Unsupported rig behavior must be reported rather than replaced with an unlabelled native model. These are CPU preparation boundaries; native viewport appearance and GPU-use retirement require separate shared-library and consumer qualification.

The domain provider declares bounded container, loot, physical-open, and lid-pose parameters separately from the complete settings candidate. It captures the active resource identity on the client, then compiles frozen inputs and prepares CPU geometry and still frames in the operation’s worker stage. The shared host owns authorization, request freshness, visibility, upload, and retirement; provider results contain copied scene data and capability facts.

Profile resolution is typed compiler output, retained with both the published generation and isolated draft inputs. It distinguishes selected, missing, refused, and disabled profiles without parsing diagnostics. Requested identities remain intact. A disabled result has no effective profile; a missing or refused selection identifies its inherited fallback and reason. This describes profile-level resolution, not ownership of every resource slot or proof that an unsaved preview is installed. Older result producers without these facts remain unknown.

Preview diagnostics preserve the compiler’s complete bounded message set in ordered groups that fit the shared fact count and text limits. Metadata and diagnostics share the same final output budget; grouping does not drop messages or turn a refusal into success.

Captured textures become still frames through re:form’s shared batch decoder, using the same workflow ledger as retiring native resources. Complete scene admission includes geometry and retained frames; the domain layer does not maintain a separate decoder, GPU allocation path, or viewport. The isolated still uses nearest sampling, clamp wrapping, and back-face culling. Each native cuboid face’s rectangular UV footprint determines whether its displayed frame is opaque, binary cutout, or translucent; native world-layer facts remain separate. Classification preserves captured geometry and lighting flags. It uses cached tile summaries and exact boundary samples, with cancellable sampling capped at eight times the declared decoded-pixel allowance. Temporary tile tables have a separate working-byte ceiling equal to the output allowance, and footprint-cache entries are bounded by the admitted triangle count. These bounds describe CPU preparation rather than live-atlas, shader, world-AO, animation, or frame-rate parity.

The isolated preview then selects reference lighting. It records the original native AO request separately and retains geometry, UVs, normals, shading direction, and emission while deliberately omitting world ambient occlusion from the displayed scene. Inspection identifies both the native request and the effective policy. This does not change installed models or world rendering, and re:form still refuses an unadapted scene that requests unsupported world AO.
